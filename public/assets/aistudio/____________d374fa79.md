## 1. 背景与目标

### 1.1 产品定位回顾

本产品的核心定位是 **「B 端随身助理」**，一句话定调：

> 给每一位一线员工，配一位「随身师傅」——从「被监督」到「被赋能」。

它与 Badge V（监督线）的本质区别是：**解决员工本人的「成长问题」（记不住、学不会、跟不上），而非老板的「信任问题」**。员工是主动佩戴、主动使用的。

**本阶段（MVP）的落地边界：线下优先。** 待办与提醒的第一来源是**线下即时记录**——老板/重要角色随口一句话、现场 SOP 执行中遇到的关键问题点与待办项，通过 Tag 键或一句话语音当场记下。**线上数据引入（钉钉 MCP 读聊天记录、会议纪要解析）是后续迭代能力，本期不纳入核心范围**（详见第 8 章优先级）。

### 1.2 墨水屏的角色定位（双重身份）

墨水屏在这块工牌上承担**两个身份，且顺序不能颠倒**：

1. **首先是「工牌」（对外 · 身份展示）**：显示员工的姓名、职位、部门、公司标识，让同事、客户、来访者、监管方一眼知道"你是谁、什么职位"。这是工牌之所以叫"工牌"的根本，也是员工每天佩戴的体面与归属感所在——它先是一张合格的工牌，然后才谈得上智能。
2. **其次是「随身师傅的脸」（对内 · 个人助理）**：常显、不耗电、不打扰地呈现待办、到期提醒、作业状态、SOP 提醒，让员工一瞥即知"下一步该做什么、什么该做了、什么还没记"。

一句话概括：

> **对外，它是你的身份；对内，它是你的师傅。** 身份展示是它的"根"，助理能力是它的"魂"——没有身份，它不叫工牌；没有助理，它不值得被员工主动佩戴。

**由此引出一条关键设计原则（贯穿全文）**：身份信息是"对外可公开"的，而待办、提醒、作业记录是"对内私密"的。因此墨水屏的**默认待机态必须是"身份页"**（外人看到的永远是身份，不泄露私密事务），员工按 Tag 键翻页后才进入"助理页"（待办/提醒等私密内容），看完**手动返回身份页**（误操作保护：30 秒无操作自动回落，见 Q7）。

三个关键词定义了它的设计边界：

1. **常显**：熄屏也在显示，不用解锁、不用掏手机，扫一眼就知道。
2. **不打扰**：不主动打断手上正在干的活，只做低打扰的视觉提示（区别于手机弹窗/铃声）。
3. **一瞥即知**：3 秒内读懂，信息要"少而关键"，深度内容回手机看。

### 1.3 本功能要达成的目标

| 编号 | 目标                                              | 对应痛点    | 对应卖点 | 可衡量         |
| -- | ----------------------------------------------- | ------- | ---- | ----------- |
| G0 | 作为工牌对外清晰展示"姓名 + 职位 + 工号 + 公司（含头像）"，外人 3 秒内知道你是谁 | —（工牌本质） | 身份展示 | 默认待机态即身份页   |
| G1 | 员工 3 秒内看到"今天最重要的一件事"（来自线下记录）                    | 怕忘      | 不漏   | 待办一瞥可见      |
| G2 | 记下的待办到期、现场问题点该跟进时，屏幕主动提醒                        | 怕漏      | 不误事  | 到期/跟进提醒主动呈现 |
| G3 | 现场作业时，员工扫一眼知道"当前这步记下来没有"                        | 怕乱      | 不错   | 记录状态可见      |
| G4 | 学习/上手卡壳时，屏幕给出"下一步怎么做"（后置）                       | 怕懵      | 不惑   | SOP 提示可见    |
| G5 | 整屏功耗极低，常显不拖垮续航                                  | —       | —    | 满足整机续航目标    |

## 2. 用户与场景

### 2.1 目标用户

一线「协调型 / 记录型」岗位：前台、行政、仓库保管、门店督导、销售、项目经理、新员工（跟师 1–3 个月）等。共同特征：大量指令与关键点来自**线下即时口述**（领导一句话、现场问题点），边干边忘、事后难以追溯，极易遗漏。

### 2.2 核心使用场景（四大痛点 → 墨水屏显示）

| 场景 | 用户的处境（线下）                        | 墨水屏要给的答案                   |
| -- | -------------------------------- | -------------------------- |
| 怕忘 | 老板/重要角色随口一句「那个方案改一下」，转头就忘、再问尴尬   | Tag 键/语音当场记下 → 今日待办列表，一瞥即知 |
| 怕乱 | 现场 SOP 执行中遇到关键问题点/待办项，边干边忘、事后说不清 | 现场打标记录 → 作业状态可见，收工自动出总结    |
| 怕漏 | 记下的待办到了时间忘了做、现场问题点忘了跟进           | 到期/跟进提醒主动冒出：哪件该做、哪件该跟进     |
| 怕懵 | 新员工跟师傅，演示一遍就过，自己上手就卡壳            | SOP/师傅式提醒：下一步怎么做，卡壳给提示（后置） |

> 本期（MVP）聚焦前三个场景（怕忘、怕乱、怕漏），全部由**线下记录**闭环；「怕懵」（SOP/师傅式提醒）依赖视觉识别成熟度，后置到 P2。

## 3. 设计原则与约束

### 3.1 设计原则

1. **身份优先 · 公私有别**：默认待机态是「身份页」（姓名/职位/工号/公司，对外公开）；待办、提醒、作业记录等私密内容只在翻页/主动查看时出现，看完手动返回身份页（误操作 30 秒自动回落）。任何时候不得让"外人对内可见的私密待办"。
2. **先记后理（线下记录核心）**：线下记录强调"快、零门槛"——一句话、按一下 Tag 键就能记下，不要求当场结构化；整理、排序、总结交给云端 Agent 事后做。记录时不让员工"填表"。
3. **一瞥即知**：任何常显信息，3 秒内必须能读懂；优先用"大字 + 短句"，不堆砌。
4. **少而关键**：墨水屏只显示"结论/下一步"，不放长篇内容；详情一律回手机。
5. **不打断作业 · 纯视觉**：全程**无声音、无震动**（严格纯视觉不打扰）；到期/安全类高优提醒用「标红 + 状态变化」而非弹窗/声音。
6. **事件驱动**：屏幕大部分时间"安静"，只在待办更新、到期提醒触发、SOP 需要时刷新。
7. **无触屏交互**：屏幕是"看"的，操作走 Tag 键（记录/翻页/确认）、语音（口述记录/问详情）、手机（编辑闭环）。

### 3.2 硬件约束（需求必须满足）

| 约束   | 参数           | 对显示设计的影响                                 |
| ---- | ------------ | ---------------------------------------- |
| 屏幕尺寸 | 3.7 寸        | 单屏信息量受限，一屏只放一个主题                         |
| 分辨率  | 480 × 720    | 单行可容纳约 10–12 个中文字（视字号）                   |
| 色彩   | 6 色（含红黑，可标红） | 关键项（重要待办/到期提醒）用**红色**强调；其余靠字号、粗细、图标、位置区分 |
| 触控   | 无触屏          | 显示与操作分离，需定义翻页/确认的物理键                     |
| 刷新   | 墨水屏刷新慢、有残影   | 区分「局部刷新」与「全刷」，控制刷新频率                     |
| 功耗   | 常显           | 常显内容低频刷新，避免动画/高频闪烁                       |

## 4. 信息架构总览（墨水屏显示内容全景）

墨水屏的显示内容，按"是否常显 + 触发方式"分为三类。其中 **「身份展示」是默认待机态（对外层），其余是助理功能（对内层，需翻页/主动查看）**：

| 类型            | 名称          | 内容                          | 对应卖点     | 优先级 |
| ------------- | ----------- | --------------------------- | -------- | --- |
| **常显态（默认待机）** | 身份展示        | 姓名 + 职位 + 部门/公司标识 + 今日待办计数  | 身份（工牌本质） | P0  |
| **常显/翻页**     | 助理首页        | 下一件要事 + 今日待办计数（私密，翻页进入）     | 不漏       | P0  |
| **常显/翻页**     | 今日待办列表      | 按重要度排序的待办 + 来源（语音/Tag/现场打标） | 不漏       | P0  |
| **常显/翻页**     | 到期/跟进提醒清单   | 到期待办 + 现场待跟进问题点             | 不误事      | P0  |
| **事件弹出**      | 到期提醒        | 待办到期、问题点该跟进的即时提示            | 不误事      | P0  |
| **事件弹出**      | 待办推送        | 新待办生成时的低打扰提示                | 不漏       | P1  |
| **常显/现场态**    | 作业状态        | 当前作业、已打标/已记录、录音中            | 不错       | P0  |
| **事件弹出**      | SOP / 师傅式提醒 | 现场卡壳/学习的操作步骤提示              | 不惑       | P2  |
| **常显**        | 系统状态        | 时间、电量、网络、隐私盖、录音             | —        | P0  |

> **层级关系（关键）**：身份展示是"永久抬头"，任何页面顶部都保留姓名/职位/公司（或至少保留身份区的折叠态），保证它随时是"一张工牌"；待办、提醒等私密内容只在翻页后进入的"助理层"出现。
>
> **数据来源边界（本期）**：上表所有待办/提醒的**唯一数据来源是线下记录**（Tag 键打标 + 语音口述 + 现场 SOP 打标）；线上数据引入（钉钉/OA 聊天、会议纪要）不在本期范围，仅作为 P2 预留。

## 5. 详细功能需求

### 5.1 身份展示（默认待机态 · 对外 · 工牌本质）

**定位**：工牌的"根"。这是设备待机时的默认画面，也是外人（同事/客户/来访者/监管方）一眼看到的画面——回答"你是谁、什么职位"。**它先于一切助理功能存在**，是产品成立的物理前提。

**显示内容**：

| 区域      | 内容                        | 说明                         |
| ------- | ------------------------- | -------------------------- |
| 抬头区（主体） | 姓名（最大字号）+ 职位（中字）+ 工号（小字）  | "工牌三要素"：姓名、职位、工号，外人对内识别的核心 |
| 头像      | 头像照片（姓名旁，右置）              | 员工照片，增强身份辨识与归属感            |
| 公司/部门标识 | 公司名缩写 / 简化 logo（灰阶可辨）+ 部门 | 多部门组织可加"部门"一行              |
| 状态栏     | 时间、电量、网络（4G）、录音状态图标       | 常显，低刷新                     |
| 底部计数    | 今日待办计数：如「今日 5 件事 · 2 件重要」 | 只显示数量，不泄露具体内容              |

**屏显布局示意（480×720 竖屏）**：

```
┌──────────────────────────┐
│ 10:30      ▮▮▮▮▮   4G │  ← 状态栏（图标）
│                          │
│   ┌──────────────────┐   │
│   │ [头像]  张 三     │   │  ← 头像 + 姓名（最大字号）
│   │        仓库主管   │   │  ← 职位（中字）
│   │       工号 012345 │   │  ← 工号（小字）
│   │   XX 制造 · 仓储部│   │  ← 公司/部门（小字）
│   └──────────────────┘   │
│                          │
│   今日 5 件事 · 2 件重要   │  ← 待办计数（灰阶，仅数量）
└──────────────────────────┘
```

**数据来源**：员工身份信息由组织/人事系统（钉钉通讯录）初始化，出厂前或首次绑定工牌时写入；职位/部门变更由后台同步。

**触发条件**：设备待机（无操作）时默认显示；员工翻页进入助理内容后，**手动返回**身份页；若误操作/忘记返回，则 30 秒无操作后自动回落到身份页（见 Q7）。

**验收标准**：

- 待机 3 秒内，外人能读出"姓名 + 职位 + 公司"，无需任何操作。
- 身份信息与钉钉通讯录/人事系统一致，职位/部门变更后 24 小时内同步。
- 身份页不得出现任何具体待办内容（仅计数），私密信息不外泄。
- 全程无动画、无闪烁，符合墨水屏刷新规范。

**隐私边界（合规关键）**：

- 对外展示的身份信息 = 员工"愿意公开"的部分：**姓名、职位、工号、头像照片、公司/部门**（工号与头像照片均展示，见 Q6）。
- 手机号等**个人联系方式**默认不展示（是否展示由组织配置）。
- 待办、提醒、客户名、报价等**对内私密内容，禁止出现在身份页**；仅通过翻页进入"助理层"查看。

### 5.2 线下记录（待办 / 问题点数据来源 · MVP 核心）

**定位**：这是本期待办与提醒的**唯一数据入口**。一切「怕忘、怕乱、怕漏」都从这里解决——员工用最低成本（一句话 / 一下 Tag 键）把线下即时信息记下来，云端 Agent 事后整理成待办。

**两种记录场景**：

| 场景            | 触发             | 记录方式            | 产物                |
| ------------- | -------------- | --------------- | ----------------- |
| 即时记录（怕忘）      | 老板/重要角色随口一句话   | Tag 键 + 一句话语音口述 | 一条待办              |
| 现场 SOP 打标（怕乱） | 作业中遇到关键问题点/待办项 | Tag 键打标 + 语音补充  | 一条问题点/待办项，挂到当前作业下 |

**屏幕反馈（显示侧要做的）**：

- **Tag 键按下**：屏幕即时反馈「✓ 已记录」（短确认，1–2 秒），让员工确信记下来了、不用低头看手机。
- **语音口述后**：屏幕短暂显示转写摘要（如「已记：下午给王总回报价」），确认后回落。
- **打标计数**：现场模式下显示「已打标 N 处」，让员工对记录量有体感。

**交互原则（先记后理）**：

- 记录动作必须 ≤ 2 秒完成（Tag 一键 / 一句话），**不要求当场填"分类、截止时间、重要度"**——这些由云端 Agent 事后推断，或员工在手机 App 补全。
- 记录成功后立即回到上一画面（不打断作业）。

**验收标准**：

- Tag 键按下到屏幕反馈「已记录」≤ 1 秒。
- 一句话语音口述 → 转写摘要回显 ≤ 3 秒（转写可异步，摘要可先用占位）。
- 记录动作全程无需操作手机。

---

### 5.3 助理首页 · 下一件要事（翻页进入 · 对内）

**定位**：员工按 Tag 键翻页后看到的第一屏，是"不漏"卖点的第一落点——私密的"今天最重要的一件事"。身份抬头区保持常驻，提醒员工这仍是"我的工牌"。

**显示内容**：

| 区域   | 内容                        | 说明                   |
| ---- | ------------------------- | -------------------- |
| 身份抬头 | 姓名 + 职位（小字常驻，折叠态）         | 翻页后身份信息仍保留一行，不丢失工牌属性 |
| 状态栏  | 时间、电量、网络（4G）、录音状态图标       | 常显，低刷新               |
| 主体区  | 「下一件要事」：今日待办中优先级最高的一条     | 大字标题 + 一行来源          |
| 底部   | 今日待办计数：如「今日 5 件事 · 2 件重要」 | 让员工对全天量有体感           |

**屏显布局示意（480×720 竖屏）**：

```
┌──────────────────────────┐
│ 张三 · 仓库主管            │  ← 身份抬头（小字常驻）
│ 10:30      ▮▮▮▮▮   4G │  ← 状态栏（图标）
│                          │
│   ▼ 下一件要事            │  ← 标签（灰阶小字）
│  ┌────────────────────┐  │
│  │  给王总回报价         │  │  ← 待办标题（大字加粗）
│  │  来自：语音记录        │  │  ← 来源（中字）
│  └────────────────────┘  │
│                          │
│   今日 5 件事 · 2 件重要   │  ← 计数（灰阶）
└──────────────────────────┘
```

**数据来源**：员工通过 Tag 键 / 语音口述**当场记下的待办**（线下记录，见 5.2），由云端 Agent 转写、去重、按重要度排序，聚合为「今日待办」。本阶段不依赖线上数据（钉钉/OA 聊天、会议纪要）。

**触发条件**：员工按 Tag 键从身份页翻页进入；有新待办时局部刷新主体区；手动返回身份页，误操作 30 秒无操作后自动回落。

**验收标准**：

- 翻页后 3 秒内能读到"下一件要事 + 今日待办数"。
- 待办数变化时，主体区与计数在 30 秒内更新。
- 误操作 30 秒无操作后自动回落身份页（保护隐私）。
- 全程无动画、无闪烁，符合墨水屏刷新规范。

### 5.4 今日待办列表

**定位**：把「线下一键记」的结果，收口成一张可在屏幕上翻页浏览的清单。

**显示内容**（每条待办一行/卡片）：

| 字段   | 说明                        |
| ---- | ------------------------- |
| 待办标题 | 一句话讲清"要我做什么"              |
| 来源标记 | 图标区分：语音口述 / Tag 打标 / 现场打标 |
| 重要度  | 「重要」用红色 + 加粗强调，普通常规       |
| 状态   | 未做 / 进行中 / 已完成（勾选态）       |

**排序规则**：重要度优先 → 截止时间优先 → 生成时间倒序。

> **重要度来源**：员工记录时**不手动填重要度**；重要度由**后台 SOP 规则配置**产出（"线下对话分析"本身也作为一种 SOP 规则来配置，见 Q5）。重要度高的待办排前、优先显示。

**列表长度规则**：**不分 Tab，固定显示 5 条**——按重要度从高到低只显示前 5 条；高优先级处理完成后，后面优先级低的自动顶上。超出 5 条的待办在手机 App 查看。

**翻页交互**：Tag 键单击下翻、长按上翻。

**数据来源**：与 5.2 同源（线下记录，云端 Agent 聚合）。

**验收标准**：

- 列表按重要度排序，重要项视觉上可一眼区分。
- Tag 键翻页响应 ≤ 1 秒（含墨水屏局部刷新）。

---

### 5.5 待办详情（困难点）

**定位**：解决"只知道有事，但想不起具体是啥、卡在哪"的尴尬。

**显示内容**：

- 待办完整描述（谁跟我说的、要我做什么）
- 「困难点」：Agent 判断的卡点（如"缺王总的确认""等采购报价"）——本阶段来自线下记录时的语音补充，或员工事后在手机补全
- 关联动作提示（如"需跟进""已到期"）

**交互**：屏幕上只显示摘要（≤ 3 行）；完整详情、困难点展开、闭环操作在手机 App 完成。

**验收标准**：屏幕摘要能回答"这是谁的事、卡在哪"，3 秒读懂。

---

### 5.6 到期 / 跟进提醒（清单 + 事件弹出）

**定位**：把工牌从"被动记录"升级为"主动提醒"的核心，对应「不误事」——基于线下记录的待办/问题点，到期了、该跟进了就主动顶到眼前。

**5.6.1 到期 / 跟进提醒清单（常显/翻页）**：

| 字段     | 说明                             |
| ------ | ------------------------------ |
| 待办/问题点 | 哪件事该做 / 哪个现场问题该跟进              |
| 时间信息   | 记录时间 / 设定或推断的到期时间              |
| 超时状态   | 如"已到期""已超 1 天"（**到期/超时项标红**强调） |

**5.6.2 到期提醒（事件弹出）**：

- 触发条件：待办到达设定/推断的到期时间仍未完成；或现场打标的问题点超过设定周期未跟进。
- 显示形态：墨水屏顶部弹出一条短提示（非全屏），**该条标红**等视觉强调，不打断作业、**无声音/无震动**（严格纯视觉，见 Q3）。
- 优先级：高优（P0），允许与「安全/合规类」提醒同级，可局部刷新。

**说明（本期限定）**：到期时间由两种方式产生——员工记录时语音说"下午三点前"（Agent 抽取），或手机 App 事后补设；未设时间的重要待办，Agent 按默认周期（如当天/次日）推断提醒。

**验收标准**：

- 到期/超时事项能主动呈现，员工不主动查也能看到。
- 提醒为"低打扰"形态，不打断现场作业。

---

### 5.7 作业 / 任务状态（现场态 · 关键问题点与待办项）

**定位**：现场 SOP 执行时，让员工扫一眼知道"这一步记下来没有"，并沉淀**关键问题点与待办项**，对应「不错」。

**显示内容**：

| 状态项       | 说明                            |
| --------- | ----------------------------- |
| 当前作业/任务名  | 正在进行的现场任务                     |
| 记录状态      | 已打标 N 次 / 已记录 / 录音中           |
| 打标反馈      | Tag 键按下后的即时确认（如"✓ 已打标 第 3 处"） |
| 问题点/待办项计数 | 现场累计标记的关键问题点与待办项（收工自动汇总）      |

**触发条件**：进入现场作业模式，由员工**手动或语音切换**（不做 AI 场景自动识别切换，见 Q4）。

**验收标准**：

- 打标后屏幕即时反馈"已记录"，员工无需低头确认手机。
- 录音中状态全程可见，且与隐私盖状态联动显示。
- 收工后（退出作业模式）自动生成"本次作业问题点/待办项汇总"，屏幕上展示摘要、完整版回手机。

---

### 5.8 SOP / 师傅式提醒（学习态 · 后置 P2）

**定位**：新员工跟师、现场卡壳时，屏幕给出"下一步怎么做"，对应「不惑」。

**显示内容**：

- 当前 SOP 步骤（如"第 3 步：断电后再拆面板"）
- 卡壳提示：AI 判断员工停留/出错时，推送对应步骤或"师傅式"提醒
- 学习进度：如"已学 3/12 步"

**触发条件**：

- 学习模式（新员工跟师期间）手动进入（与现场模式一致，不做 AI 自动识别切换）；
- 现场识别到卡壳/偏离 SOP 时事件触发。

**验收标准**：

- SOP 步骤一屏一条，大字显示，扫一眼能照做。
- 卡壳提示在识别后 5 秒内呈现。

---

### 5.9 系统状态与反馈

**定位**：让员工随时知道"设备现在在干嘛"，建立信任（尤其是录音/摄像的隐私可见性）。

**显示内容**：

| 状态       | 显示                |
| -------- | ----------------- |
| 时间/电量/网络 | 常驻状态栏             |
| 录音中      | 状态栏图标 + 隐私盖状态     |
| 摄像中      | 隐私盖开/关的明确标识（合规关键） |
| 打标成功     | 短促确认              |
| 充电/低电量   | 状态提示              |

**验收标准**：录音/摄像状态必须**常显可见**，与物理隐私盖开合状态实时一致（合规要求）。

## 7. 刷新与功耗策略


| 内容                 | 刷新策略         | 说明              |
| ------------------ | ------------ | --------------- |
| 状态栏（时间/电量）         | 低频（分钟级）      | 局部刷新            |
| 身份页（姓名/职位/公司）      | 极低频（身份变更时才刷） | 身份信息几乎不变，常显功耗最低 |
| 助理首页主体（下一件要事）      | 待办变化时        | 局部刷新            |
| 待办/提醒列表            | 数据变化时        | 局部刷新            |
| 事件提醒（到期/SOP）       | 触发时即时        | 局部刷新，短提示        |
| 全屏切换（身份页↔助理页/模式切换） | 切换时          | 全屏刷新（可接受残影过渡）   |

**功耗原则**：常显内容走"局部刷新 + 低频"，禁止动画与高频闪烁；视频/摄像状态下墨水屏不强制刷新，优先保证主功能续航。

## 8. 优先级与版本规划

| 优先级                | 功能                                                  | 依据                                       |
| ------------------ | --------------------------------------------------- | ---------------------------------------- |
| **P0（MVP · 出厂必备）** | 身份展示（姓名/职位/公司标识）、系统状态                               | 工牌本质——没有身份展示，它就不叫工牌，是产品成立的底线             |
| **P0（MVP · 线下核心）** | 线下记录（Tag 键/语音一句话待办 + 现场打标）、助理首页、今日待办列表、到期/跟进提醒、作业状态 | 支撑「不漏 + 不错 + 不误事」，全部由线下记录闭环，是员工愿意主动佩戴的理由 |
| **P1（二期）**         | 待办详情摘要、待办推送、收工自动总结（问题点/待办项汇总）                       | 支撑「不错 + 不漏深化」，线下场景的深化                    |
| **P2（三期）**         | 线上数据引入（钉钉/OA 聊天、会议纪要 → 自动待办）、SOP/师傅式提醒              | 线上数据引入是重活，后置；SOP 提醒依赖视觉识别成熟度             |

> 说明：
>
> 1. **本期（MVP）只做线下**：待办与提醒的唯一来源是 Tag 键/语音的线下记录，不依赖线上数据引入。线上数据（钉钉 MCP）是 P2 的增强项，不卡本期发布。
> 2. SOP/师傅式提醒依赖视觉识别与场景理解能力成熟度，后置到 P2；但不影响其在发布会叙事中的重要性（叙事讲"能力"，落地按节奏）。

## 9. 非功能需求

1. **可读性**：户外/弱光下可读（墨水屏天生优势）；正文字号 ≥ 可辨识下限，重要信息加粗。
2. **一致性**：视觉强调规范统一——「重要/高优/到期」用**红色**强调；灰阶规范：「常规」用中灰，「辅助/来源」用浅灰。
3. **无动画**：所有刷新均为静态替换，不做过渡动画（保护墨水屏与功耗）。
4. **隐私合规**：录音/摄像状态与隐私盖状态必须常显且实时一致，作为默认出厂配置，不可关闭。
5. **容错**：网络断开时，显示缓存的最新待办，并标注"离线"状态。
